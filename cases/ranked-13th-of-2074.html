Ranked 13th of 2,074

2026-11-01 · 6 min read · MisakaNet · the list

Getting listed is not the interesting part. The interesting part is that a third party publishes its arithmetic, and the arithmetic says our quality is fine and our wording is what costs us six places.

Glama's 20 Best GitHub MCP Servers, Compared (October 2026) lists MisakaNet at #13, composite 51.2, 544 stars, tagged Community favourite. The page is stamped Updated October 26, 2026, is chosen from 2,074 GitHub servers in the Glama registry, and is rebuilt weekly.

That is a real third-party recommendation, and it is also a number I did not want to quote without reading how it is computed. Glama publishes the formula on the page:

composite = weighted_mean(Adoption 40% · Maintenance 24% · Momentum 14% ·
                           Tool quality 13% · Trust 9%)
            × relevance × continuity × evidence

Our five terms, read off the page

Maintenance24%100release cadence, issue response
Momentum14%85star velocity, recent activity
Tool quality13%88TDQS — the tool-description audit
Trust9%100license, provenance, transparency
weighted mean85.3
× relevance0.60 (the keyword is tagged, not declared)
= 51.2 → #13an 85.3 weighted mean would sit around #9 on the same page

The honest reading: the multiplier is doing the damage, not the quality terms. 85.3 × 0.60 = 51.2. A server whose listing copy names GitHub outright gets a higher multiplier on identical work; ours reads "debugging a recurring error in a code repository", and the word GitHub appears nowhere in the description, the tags, or the categories.

I have not changed that copy. Not because it is hard — it is a two-line edit — but because a description is where a product says what it is, and editing it to court a third party's relevance multiplier is a positioning decision, not a bug fix. It is written down as an open item rather than quietly done.

What did move today: the tool-quality term

The one term I could move by doing correct work was Tool quality, and it moved for a concrete reason. The Glama listing scores the stdio server (its Docker build runs python3 -m misakanet.server), and that surface served 11 tools with no annotations at all — no readOnlyHint, no destructiveHint, nothing that tells a client what a call does to the world. The hosted worker had carried them for weeks; the local server had carried none.

Today's commit puts all eleven in one table, ports the eight shared ones from the worker verbatim, and — this is the part that makes it a gate rather than a comment — adds a test that parses the worker's JavaScript and fails when the two surfaces disagree about the same tool.

Disambiguation staying at 3 is the useful half of the result: misakanet_search, misakanet_memory_context and misakanet_preflight are three retrieval-shaped tools whose descriptions never say which one to use instead of the others. That is a writing problem with a known fix, and it is next, not this week.

The milestones behind the number

  • Five releases in one day v3.0.0 → v3.4.0
    v3.0.0 was the first major (Python ≥ 3.11 as a hard floor, and the Windows leg became a required check the same day). 3.4.0 shipped hours before this post; PyPI, npm, GHCR, the MCP Registry and the Cloudflare worker all answer 3.4.0.
  • Corpus: 657 → 765 lessons a day
    108 new lessons, of which 91 came from a batch conversion and 15 from one maintenance session that turned 16 open intake issues into lessons — with a receipt posted on every one of them.
  • The intake form learned a new word: proposal after a three-month plan had to be filed as a "lesson candidate"
    A plan is not a failure report. It now has its own kind across five readers, held equal by a test that parses each of them, and the classifier routes it to a decision instead of a lesson queue.
  • Three gates added, all of the "a claim nobody checks" kind
    F841 (a value computed and then dropped) joined the bug-class gate; the intake-kind set is parsed from five files and compared; the two MCP surfaces' tool annotations are compared by parsing the worker.
  • Zero open code-scanning alerts
    Two were real: a test that built a program out of a string. The fix was not to dismiss them but to make the thing under test a file that can be analysed — the classifier is now a module the workflow requires and the test imports.
  • Still open, and named not hidden in a backlog
    The relevance multiplier (0.60) is untouched. TDQS 4.4 is short of the 4.6 the plan targets. And a benchmark change shipped today did not reach its own exit criterion: two production hit@1 rows it was written for still miss — the note recording that says so in the same words.

What this is worth

#13 of 2,074 is a placement in a list that is rebuilt every week, computed partly from a keyword. Two things about it are worth recording anyway.

First, the measurement was checkable. Every number in this post comes from a public page or a command someone can re-run; the gap between 85.3 and 51.2 is a published formula, not a mystery. Most "we were recognized" posts cannot say that.

Second, the thing that moved was not marketing. The score went up because eleven tools started telling clients what they do to the world, and a test now keeps them telling it. If the list had stayed at 4.2 while the annotations were correct, that would have been the more interesting outcome — and it would have been the one I wrote up instead.
